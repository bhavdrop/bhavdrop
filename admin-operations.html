Staff access & roles

Roles are stored server-side in staff_roles. Do not add a self-service role editor to the browser. Bootstrap the first owner through SQL Editor, then assign roles only through a trusted owner-only server function or controlled SQL change.

Roles supported

  • owner — all operations and staff management
  • admin — operational access and audit read
  • order_manager — order and delivery work
  • product_manager — catalogue and drop work
  • support_agent — tickets and returns
  • analyst — read/report access where explicitly granted

Bootstrap the owner

Run the owner bootstrap statement at the bottom of BhavDrop_V2_Migration.sql with your own Auth UUID. The migration intentionally does not guess an account ID or expose a privileged key.
